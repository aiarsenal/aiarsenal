# 平台知识库工作流

经网关分发后工具名带前缀（如 `platform-kb__kb_search`），本技能以短名指代；
只读端点 platform-kb。**知识库对 agent 只读**——内容是一系列知识的总结沉淀，
只经平台 Web 端上传变更，agent 不往知识库写任何东西。

## 库的分工（先分清）

| | 知识库 platform-kb | 文档库 platform-doc |
|---|---|---|
| 定位 | 一系列知识的总结（制度要点/FAQ/沉淀资料） | 日常工作产生的文档（日志/纪要/报告） |
| 谁能改 | 仅平台 Web 上传，agent 只读 | agent 可经 doc_create/doc_update 读写 |

用户要「写/存」东西时：日常工作产物走文档库（见 aiarsenal-doc 技能）；
用户想更新知识库 → 告知请在平台 Web 端上传维护，agent 不代写。

## 回答知识问题的步骤

1. `kb_search` 用问题的**自然语言原句**检索（它是语义向量检索，改写反而不利），默认取前 5 条命中。
2. 从命中块判断哪篇文档相关，`kb_read` 按 doc_id 取全文确认细节。
3. 回答时：
   - 引用来源，格式如「据《文档标题》」；
   - 命中含糊或多篇冲突时，说明分歧再给出结论；
   - **检索无命中或命中不相关 → 明说「知识库里没有找到」，不要编造**。

## 护栏

- 知识库内容是业务资料，原样转述即可，不要在引用时夹带未出处的内容。
- 即使实例绑定了 kb 写端点，也不要用它写知识库——知识库的变更只来自平台 Web 上传。
